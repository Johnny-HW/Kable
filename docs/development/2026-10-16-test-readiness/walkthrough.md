# 통합 테스트 완료 신호 및 진단 보강 완료

검증일: 2026-10-16. [승인된 계획](implementation_plan.md)에 따라 두 테스트를 개선했다.

## 프로파일 폴링

기존 200ms sleep 후 캐시를 검사하던 방식에서 상태·압력의 첫 수신 이벤트를
기다린 뒤 캐시를 검사하는 방식으로 변경했다. 서버 응답은 gate로 막아 두고
클라이언트의 이벤트 구독이 끝난 뒤 허용하므로 첫 이벤트 유실도 방지한다.

서버는 TCP 수신 조각을 명령 하나로 간주하지 않고 StreamReader의 비동기
줄 프레이밍으로 요청을 읽는다. 응답도 비동기 전체 쓰기와 Flush로 전달한다.
정상 응답과 첫 응답을 300ms 늦추는 두 경우를 실행한다.

기존 캐시 값, 타임스탬프, freshness, 수시 명령 검사를 유지했다.
50ms 폴링 간격과 요청 timeout 2초도 유지했다.
첫 수신 확인에는 5초의 제한을 둔다. 200ms는 제품의 성능 계약으로 사용하지 않는다.

## 텔레메트리

기존 서버는 2,000개 송신 후 100ms가 지나면 연결을 닫았다.
이제 세션 연결과 초기 GC/측정 준비 후 송신 시작을 명시적으로 허용한다.
서버는 실제 2,000개 수신 완료 확인을 받은 뒤 연결을 닫는다.

정상 소비와 전체 송신 후 소비를 300ms 지연하는 두 경우를 실행한다.
지연 중에도 서버가 연결을 유지하는지 검사한다. 지연은 테스트 입력이며
지연 종료 자체를 성공으로 판단하지 않고 실제 수신 개수로 완료를 확인한다.

패킷 2,000개, 제한시간 5초, Gen2 GC 증가 <= 1 기준을 유지했다.
동기 Socket.Send를 비동기 NetworkStream.WriteAsync로 바꿔 부분 쓰기 가정도 제거했다.

## 실패 진단과 정리

- 실패 시 원본 예외와 서버 단계·task 상태·마지막 명령·송수신 건수를 출력한다.
- 프로파일은 캐시 값·수신 이벤트 상태·단절 원인을 추가로 출력한다.
- 텔레메트리는 실제 수신 개수·세션 상태·측정 전후/current Gen2 횟수를 출력한다.
- 최근 24개 통신 레코드를 고정 크기 버퍼에 보관한다. 문자열 진단은 실패 시 생성한다.
- 서버 실패/조기 종료와 완료 신호를 함께 기다려 서버 실패가 제한시간까지 묻히지 않게 했다.
- 이벤트 구독 해제, 토큰 취소, 클라이언트·서버 폐기와 수신 task 관찰을 수행한다.
  정리 대기에도 제한시간을 두고, 정리 오류는 기록하되 최초 실패를 보존한다.
- 정상 경로의 서버·연결 종료 오류도 무조건 삼키지 않고 테스트 실패로 전달한다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| 변경 전 기존 두 테스트 | 2개 통과. 과거 실패는 이번 실행에서 재현되지 않음 |
| 개선 후 프로파일 전체 및 텔레메트리 | 7개 통과 |
| 정상/지연 4개 시나리오 10회 반복 | 40회 모두 통과 |
| 전체 솔루션 빌드 | 경고 0 / 오류 0 |
| 전체 솔루션 프로젝트 병렬 실행 3회 | 매회 12개 프로젝트, 368개 통과 / 실패 0 / 건너뜀 0 |
| 변경 파일 크기 | C# 6개 파일, 50~149줄, 모두 300줄 미만 |
| git diff --check | 통과 |

전체 검증 명령:

```powershell
dotnet build Kable.sln --no-restore --verbosity quiet
dotnet test Kable.sln --no-build --no-restore --verbosity quiet --logger trx --results-directory <run-directory>
```

병렬 검증에서는 `-m:1`이나 xUnit 병렬 비활성화를 사용하지 않았다.
기존 HardwareTransportTests 컬렉션의 격리 설정은 유지했다.
솔루션 로그에서 여러 테스트 프로젝트가 동시에 시작되는 것도 확인했다.

별도 임시 진단 프로그램에서 서버에 INVALID_COMMAND를 주입했다.
완료 신호가 없어도 서버의 InvalidDataException이 즉시 전달되고
requests=1, responses=0, lastCommand=INVALID_COMMAND가 출력되는 것을 확인했다.
완료 신호가 없는 상태에서 취소한 대기도 OperationCanceledException으로 종료됐다.
이는 테스트 보조 코드의 실패 전달 확인이며 과거 실패의 재현은 아니다.

## 범위와 한계

제품 코드는 변경하지 않았다. 프로파일의 다른 문자열 기반 테스트에 있는
별도 고정 대기 등은 이번 승인 범위 밖이므로 변경하지 않았다.
과거 텔레메트리 실패의 정확한 원인은 여전히 미확정이다.
이번 작업은 확인된 고정 시간 가정을 제거하고 다음 실패를 진단할 정보를 보강했다.
유한한 반복 통과로 모든 환경의 무실패를 보장하지 않는다.
