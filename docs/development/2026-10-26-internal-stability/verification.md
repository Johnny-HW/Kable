# 내부 안정성 개선 검증 — 2026-10-26

## 적용 내용

- Modbus 채널: 전체 요청 timeout, 송신 후 실패 시 Safe-Close, Open/Close/Dispose 직렬화.
- PCAP: 유한 기록 큐와 조회 버퍼, 기록 워커, 소유 스냅샷, 종료 배출, 오류·누락 수 공개.
- 세션: 옵저버가 없으면 FIFO/CID 요청·응답의 관측용 원시 바이트 복사를 생략.
- Modbus 코덱: 불가능한 7바이트 요청 접두부를 CRC 하위 바이트로 배제하여 잡음 복구.
- 잡음 테스트: 입력이 줄지 않는 재시도를 즉시 실패시켜 무한 반복 방지.

## 코덱 회귀의 재현과 수정

정상 응답 `01 02 01 03 E1 89` 앞에 잡음 50바이트를 붙이면,
수정 전 작업본은 오프셋 49의 `9B 01 02 01 03 E1 89`에서 멈췄다.
7바이트 응답 후보는 CRC가 틀렸고, 8바이트 요청 후보는 마지막 바이트를 기다렸다.
하지만 요청 후보의 CRC 하위 바이트는 이미 수신되어 있었다.
계산값 `B1`과 수신값 `89`가 다르므로 정상적인 요청 접두부일 수 없다.

짧은 Read 프레임 처리를 별도 partial 파일로 분리했다. CRC가 유효한 완성 응답을
먼저 반환하고, 요청 또는 응답이 여전히 완성될 수 있으면 입력을 보존한다.
두 후보가 모두 불가능할 때만 1바이트를 버린다. 연속·다중 세그먼트 입력,
상위 주소 바이트가 큰 분할 요청, 뒤에 데이터가 붙은 응답, 힙 할당 여부를 검증했다.

추가 테스트를 먼저 실행하여 7개 실패를 확인했고, 구현 후 관련 35개가 모두 통과했다.
수정 후 같은 재현 입력은 오프셋 50에서 정상 응답을 반환한다.

## 최종 검증 결과

| 검증 | 결과 |
| --- | --- |
| `dotnet build Kable.sln -c Release --no-restore` | 성공, 경고 0 / 오류 0 |
| `dotnet test Kable.sln -c Release --no-build -m:1` | 13개 프로젝트, 459개 통과 / 실패 0 / 건너뜀 0 |
| Core 전체 테스트 | 멈췄던 잡음 복구 테스트를 포함하여 350개 통과 |
| `dotnet pack Kable.sln -c Release --no-build --no-restore` | 성공, 로컬 패키지 14개 생성 |

전체 테스트에는 필터를 적용하지 않았다. 90초 중단 감시와 TRX 로거를 활성화했다.
최초 병렬 실행의 시간 제한·성능 임계값 실패는 최종 순차 실행에서 통과했다.
패키징에는 `Kable.Generators`의 NU5128 프레임워크 그룹 경고와 패키지 README
미포함 안내가 남아 있다. 이번 수정에서 패키지 구성이나 버전은 변경하지 않았다.

로그는 `%TEMP%`의 `kable-stability-build-final.log`,
`kable-stability-tests-final.log`, `kable-stability-pack.log`에 저장했다.
TRX는 `%TEMP%/kable-stability-final-results/`, 로컬 패키지는
`%TEMP%/kable-stability-nupkgs/`에 저장했으며 게시하지 않았다.

## 변경 보존

기존 Protocol Pack·생성기·코덱 작업본을 보존했다. Modbus 코덱의 커밋에는
이번 partial 분리와 짧은 Read 판별 진입점만 선택적으로 포함했다.
작업 시작 전의 나머지 미커밋 변경 8개 파일은 그대로 남겨두었다.
