# 내부 검토 3건 개발 완료 보고

검증일: 2026-10-16

## 구현 결과

1. Modbus FC02/03/04 읽기 응답에서 요청 개수에 따른 기대 바이트 수,
   byte count 필드, 실제 payload 길이를 배열 생성 전에 비교한다.
   데이터 부족을 false로 채우거나 부족한 레지스터 배열을 성공 반환하지 않는다.
   일치하지 않으면 `InvalidOperationException`을 반환한다.
2. 송신 펌프가 큐별 미완료 대기 작업을 유지하고 선택된 대기만 교체한다.
   종료 시 남은 작업을 await하며 정상 취소를 처리하고 다른 예외를 기록한다.
   일반/긴급 송신 테스트에서 반대편 큐 대기 등록은 32회 송신에도 1회다.
3. CID 모드에서 타임아웃 및 연결 토큰을 생성한 뒤 CID를 등록한다.
   잘못된 timeout으로 실패한 뒤 동일 CID로 정상 요청·응답할 수 있다.

계획과 설계: [implementation_plan.md](implementation_plan.md), [design.md](design.md).

## 최초 검토의 정정

두 번째 항목은 영구적인 대기자 누수가 아니다. 단일 리더 채널은 새 대기가
등록되면 이전 대기를 취소한다. 채널에 직접 100회 대기를 등록한 실험에서
미완료 1개와 취소 99개를 확인했다.
이번 수정은 송신마다 반복되던 대기 생성·취소를 줄이고 종료 관찰을 보장한다.
메모리 누수 수정이나 세션 전체의 0-GC 달성을 주장하지 않는다.

## 범위와 제한

공개 API, FIFO 연결 종료 계약, CID timeout의 세션 유지 계약은 유지한다.
Modbus 쓰기 응답 검증, 다른 PLC 프로토콜, 기존 할당 제거는 이번 범위 밖이다.
실제 PLC 장비 시험과 장시간 메모리/성능 벤치마크는 수행하지 않았다.
송신 대기 테스트는 공개 API 확장 없이 private 채널을 감싼 계측을 사용하므로,
해당 필드 이름을 변경할 때 테스트도 함께 갱신해야 한다.
