# 응답 검증 및 비동기 대기 수명 설계

## Modbus 읽기 응답

검증은 도메인 요청 개수를 알고 있는 `ModbusTcpMaster`에서 수행한다.
프레이밍 코덱이나 범용 세션에 Modbus 규칙을 추가하지 않는다.

| 요청 | 기대 데이터 바이트 수 | 성공 조건 |
| --- | --- | --- |
| FC02 | `(count + 7) / 8` | byte count 일치 및 payload 길이 = 1 + 기대 바이트 수 |
| FC03/04 | `count * 2` | byte count 일치 및 payload 길이 = 1 + 기대 바이트 수 |

배열 생성 및 비트/레지스터 변환 전에 공통 길이 검증을 수행한다.
불일치 시 기존 오류 계열인 `InvalidOperationException`으로 실패한다.
FC02의 마지막 바이트에서 요청 범위 밖의 패딩 비트는 결과에 포함하지 않는다.
장비 예외 응답의 기존 처리는 유지한다. 쓰기 응답 검증은 이번 범위 밖이다.

## 송신 대기

송신 펌프의 지역 변수에 긴급/일반 큐 대기 작업을 각각 보관한다.
미완료 대기는 다음 반복에서 재사용하고 완료된 대기만 새로 등록한다.
긴급 큐 확인, 배치 인코딩, 단일 Flush 동작은 유지한다.
종료 시 세션 취소를 알리고 남은 대기 작업을 await하여 예외를 관찰한다.
정상 취소만 처리하고 다른 예외는 송신 루프의 기존 장애 처리에 전달한다.

테스트는 실제 채널 리더를 감싼 추적 리더로 대기 등록 수와 완료 여부를 관찰한다.
일반 송신 반복 중 긴급 큐 대기 등록이 한 번만 이루어지는지 확인한다.
테스트 전용 계측을 제품의 공개 API에 추가하지 않는다.

## CID 등록

`CancellationTokenSource(timeout)`과 연결 토큰 생성이 성공한 뒤 CID를 등록한다.
등록 후에는 기존 `finally`가 CID 제거를 책임진다.
플랫폼의 timeout 유효성 검증을 재사용하여 런타임별 허용 범위를 복제하지 않는다.
잘못된 timeout은 송신·CID 등록·연결 종료 없이 호출자에게 반환한다.
무한 timeout, 정상 응답 및 중복 in-flight CID 거부 동작은 유지한다.

## 파일 구성

기존 세션 루프에서 송신 펌프와 알람 스풀 워커를 별도 partial 파일로 이동한다.
수신·디스패치·하트비트는 기존 Loops 파일에 남겨 변경 파일을 모두 300줄 미만으로 유지한다.
이동한 알람 스풀 로직의 동작은 변경하지 않는다.
