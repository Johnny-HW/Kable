# Kable 1.9.0 release notes

Release date: **2026-10-26**.
[GitHub release](https://github.com/Johnny-HW/Kable/releases/tag/v1.9.0) ·
[NuGet](https://www.nuget.org/packages/Kable/1.9.0) · [한국어](1.9.0.ko.md)

## Changes

- **Modbus channel safety:** deadlines include waiting for the channel gate. A timeout,
  cancellation or failure after encoding starts closes the connection, so a late response
  cannot be reused by the next request. Open, requests and shutdown share a gate;
  Close/Dispose cancel active connection attempts and I/O and await cleanup.
- **PCAP recording:** one worker writes owned payload snapshots through a finite queue.
  Successful shutdown drains accepted records before closing the stream. Queue overflow
  or disk errors stop recording and are observable without throwing on the packet producer.
- **Optional observability:** FIFO and correlation-ID requests skip `ToRawBytes()` when
  no observer is registered. Enabled observers retain the existing trace tags and contents.
- **Modbus framing:** check the already-received CRC low byte before waiting for an
  incomplete eight-byte read request. Impossible candidates yield to noise recovery;
  valid partial requests and incomplete longer responses remain buffered.
- **Generator packaging:** compiler implementation dependencies are no longer advertised
  as application runtime dependencies. NU5128 is resolved without adding a NoWarn rule.
  Windows CI validates an actual package consumer with an isolated local feed and cache.

## Public API and upgrade guidance

Existing interfaces and constructors remain available. The minor version reflects added
PCAP options and diagnostics. Corrected failure and buffer behavior can affect callers.

| Area | Behavior in 1.9.0 | Caller action |
| --- | --- | --- |
| Modbus timeout | `TimeoutException`; the deadline includes gate waiting | Account for queued requests in timeout settings |
| Modbus cancellation | Caller cancellation remains `OperationCanceledException`; in-flight failure closes the connection | Reopen explicitly with a factory returning a fresh context; do not replay writes blindly |
| Modbus shutdown | Active I/O is interrupted; Dispose is terminal | Await Close/Dispose and do not reopen a disposed channel |
| PCAP live views | Each stream is bounded and drops oldest records at capacity | Use drop counters; do not treat these views as a lossless audit log |
| PCAP overflow or disk failure | Recording stops; pending records may be discarded | Observe `Completion`/`LastError`; dispose and create a new observer to restart |
| PCAP disposal | Waits for normal drain and propagates recording errors after cleanup | Handle asynchronous disposal failures |

`PcapStreamObserver(string)` retains its signature. The additional overload accepts
`PcapStreamObserverOptions` with positive `RecordingCapacity`, `CommandCapacity`,
`PeriodicCapacity` and `AlarmCapacity`, each defaulting to 1,000 records. The recording
capacity excludes the record currently being written. Capture payloads are limited to
65,535 bytes while PCAP retains the original length.

Diagnostics are `Completion`, `LastError`, `DroppedCommandCount`, `DroppedPeriodicCount`
and `DroppedAlarmCount`. See the [PCAP contract](../ko/PCAP_RECORDING.md) and
[Modbus channel lifecycle](../ko/MODBUS_CHANNEL_LIFECYCLE.md) for detailed behavior.
Core/Kable continue to target netstandard2.0, net8.0 and net10.0; existing Windows-only
packages retain their platform requirements.

## Release verification

The committed release source was checked out separately from the development working tree.
The Release build completed with no warnings or errors; all **407 tests across 12 projects**
passed, including 335 Core tests and 8 Generator tests. The isolated generator package
consumer also passed. Tests run sequentially across projects without changing thresholds.

The release contains **13 packages at version 1.9.0**. Package release notes, internal
package dependencies and compiler-only generator packaging were checked before tagging.
The publish workflow stops on any package upload failure.

Earlier development-working-tree results of 459 tests and 14 packages included uncommitted
Protocol Pack work and are not the release counts. Protocol Pack generation and the
Kable.ProtocolPack package are outside this release. That work remains separate.

The [stability verification](../development/2026-10-26-internal-stability/verification.md)
and [packaging verification](../development/2026-10-26-generator-packaging/verification.md)
retain the earlier development history. Final release checks are recorded in
[release verification](../development/2026-10-26-release-publication/verification.md).
