# Kable 1.9.0 릴리즈 노트

상태: **배포 전**. 작성일은 2026-10-26이며 실제 배포일은 아직 정하지 않았다.
저장소의 목표 버전은 1.9.0이다. 이번 작업에서 v1.9.0 태그, GitHub Release,
NuGet 게시를 생성하지 않았다. [English](1.9.0.md)

## 주요 변경

- **Modbus 채널 안전성:** 제한시간에 채널 게이트 대기를 포함한다. 인코딩 시작 후
  타임아웃·취소·실패가 발생하면 연결을 닫아 지연 응답이 다음 요청에 섞이지 않게 한다.
  Open·요청·종료를 직렬화하고 Close/Dispose는 진행 중 연결과 I/O를 취소한 뒤 정리를 기다린다.
- **PCAP 기록:** 유한 큐와 단일 워커가 소유 복사한 패킷을 기록한다. 정상 종료는 수락한
  기록을 배출한다. 큐 초과·디스크 오류는 기록을 중단하고 상태로 공개하며 패킷 생산자에게
  기록 오류를 던지지 않는다.
- **선택적 관측:** 옵저버가 없으면 FIFO·CID 요청 모두 관측용 `ToRawBytes()` 호출을 생략한다.
  옵저버를 등록한 경우 기존 trace 태그와 내용을 유지한다.
- **Modbus 프레이밍:** 8바이트 요청의 나머지를 기다리기 전에 이미 수신한 CRC 하위 바이트를
  확인한다. 정상 요청일 수 없는 후보만 버려 잡음을 복구하고, 정상 분할 요청과 덜 들어온
  긴 응답은 보존한다.
- **Generator 패키징:** 컴파일 도구용 구현 의존성을 앱 실행용 NuGet 의존성으로 선언하지
  않도록 정리했다. 경고 숨김 없이 NU5128을 제거하고 실제 패키지 소비 검증을 Windows CI에 추가했다.

## 공개 API와 업그레이드 안내

기존 인터페이스와 생성자는 유지한다. PCAP 옵션·진단 API가 추가되어 마이너 버전을 올렸다.
다만 오류 처리와 버퍼 동작이 바뀌므로 호출부를 확인해야 한다.

| 항목 | 1.9.0 동작 | 호출부에서 확인할 내용 |
| --- | --- | --- |
| Modbus 제한시간 | 게이트 대기도 포함하며 초과 시 `TimeoutException` | 대기열까지 고려해 제한시간 설정 |
| Modbus 요청 취소 | 호출자 취소는 `OperationCanceledException`; 송신 후 실패는 연결 종료 | 새 컨텍스트를 반환하는 팩토리로 명시적 재연결; 쓰기 명령 무조건 재전송 금지 |
| Modbus 종료 | 진행 중 I/O 중단; Dispose 이후 재사용 불가 | Close/Dispose를 await하고 폐기한 채널은 다시 열지 않기 |
| PCAP 조회 스트림 | 스트림별 유한 버퍼, 가득 차면 가장 오래된 항목 삭제 | 누락 계수를 확인하고 무손실 감사 이력으로 사용하지 않기 |
| PCAP 큐 초과·디스크 오류 | 기록 중단, 대기 중 기록은 폐기될 수 있음 | `Completion`·`LastError` 관찰; 재개하려면 새 옵저버 생성 |
| PCAP 종료 | 정상 배출 대기, 정리 후 기록 오류 전파 | 비동기 Dispose의 예외 처리 |

기존 `PcapStreamObserver(string)` 생성자는 유지한다. 새 오버로드는
`PcapStreamObserverOptions`를 받으며 `RecordingCapacity`, `CommandCapacity`,
`PeriodicCapacity`, `AlarmCapacity`는 각각 기본 1,000건이고 양수여야 한다.
기록 큐 용량에는 현재 쓰기 중인 1건을 포함하지 않는다. 패킷은 최대 65,535바이트를
소유 복사하고 PCAP에는 원본 길이도 남긴다.

진단 속성은 `Completion`, `LastError`, `DroppedCommandCount`, `DroppedPeriodicCount`,
`DroppedAlarmCount`다. 상세 동작은 [PCAP 기록 계약](../ko/PCAP_RECORDING.md)과
[Modbus 채널 수명](../ko/MODBUS_CHANNEL_LIFECYCLE.md)을 참고한다.
Core/Kable의 netstandard2.0·net8.0·net10.0 지원과 기존 Windows 전용 패키지의 플랫폼 조건은 유지한다.

## 검증과 배포 상태

릴리즈 준비 과정에서 개발 작업본의 로컬 패키지 14개를 1.9.0으로 생성했다.
모두 릴리즈 요약을 포함하며 내부 의존성 선언 27개도 1.9.0으로 일치함을 확인했다.
Core·Kable·Generator의 어셈블리 버전도 1.9.0.0으로 확인했다.

2026-10-26 개발 작업본에서 13개 프로젝트의 전체 테스트 459개가 통과했다.
이후 패키징 정리에서는 Generator 테스트 21개와 독립 NuGet 소비 검증도 통과했다.
[안정성 검증 기록](../development/2026-10-26-internal-stability/verification.md)과
[패키징 검증 기록](../development/2026-10-26-generator-packaging/verification.md)에 범위를 남겼다.
이 결과에는 작업 중인 파일이 포함되어 있어 최종 릴리즈 커밋의 검증을 대신하지 않는다.

미커밋 Protocol Pack 생성 기능 등은 이 문서에서 1.9.0 확정 기능으로 발표하지 않는다.
게시 전 배포할 변경을 선택해 커밋하고, 깨끗한 체크아웃에서 검증한 뒤 태그와
`Directory.Build.props`의 `Version`이 일치하는지 확인한다. 모든 패키지 버전은 이 값에서 파생한다.
기존 게시 워크플로는 `v*` 태그 push 또는 수동 실행으로 게시할 수 있으며, 둘 다 실행하지 않았다.

실제 게시 후 한·영 문서, CHANGELOG와 README의 배포 전 표시를 실제 배포일과
릴리즈·패키지 링크로 바꾼다.
